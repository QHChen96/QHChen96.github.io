**领导：**我把客服 Agent 画好了。第一格收工单，第二格查订单，第三格查规则，第四格写回复。四个框，三个箭头，够不够科技？

**小陈：**够清楚。但我先问一句：查完订单之后，谁决定下一步？

**领导：**第三格啊。我箭头都画了。

**小陈：**那您画的是一条**工作流**。它很好用，别为了叫 Agent 硬给它装个方向盘。咱们还是拿虚构工单 0823 看：客户说“显示已签收，可我没收到，能退款吗？”

**领导：**你上次不还说这单需要 Agent？

**小陈：**最早那篇总览是用这张单演示“模型如何选下一步”。真要落地，还得看那一步能不能提前写清。要是客服系统已经规定：所有“签收但称未收到”的单子，固定查物流、查现行争议规则、交售后审核，那您的四格流程正合适。让模型再想一遍，主要增加账单和不确定性。

## 领导：“你把三种做法摆一张桌上。”

**小陈：**可以。同一个任务，别先问产品名，先问谁掌握方向盘。

| 做法 | 工单 0823 怎么走 | 下一步由谁定 | 适用情况 |
| --- | --- | --- | --- |
| 一次模型调用 | 给它已核实的订单事实和规则，起草一段内部回复 | 没有下一步 | 资料已备齐，只需整理文字 |
| 固定工作流 | 系统依次查订单、查现行规则、生成草稿、交客服审核 | 程序预定 | 路径稳定，分支能写清 |
| 有边界的 Agent | 看订单结果后，在允许的只读工具中决定还要查什么，或直接停下交人 | 模型在运行时选择，程序管权限和终点 | 问法变化多，所需查询无法完全预排 |

**领导：**Agent 能自己选，就让它把四格全包了？

**小陈：**别让它承包大楼保安。工单登记、查单权限、现行政策过滤、发送前审核，这些仍由程序固定执行。Agent 只负责那个确实需要临场判断的小段：查到“已签收”后，要不要再看签收凭证、争议规则，还是发现证据不够直接转人。

**领导：**听起来工作流也能分支。

**小陈：**能。能列清的分支就写在工作流里。比如“未发货”走取消订单规则，“已签收且客户称未收到”走争议规则。只有碰上无法预先穷举、而且继续查证有收益的情况，才考虑 Agent。名字不影响客户有没有收到货，路径和权限才影响。

## 领导：“那这次到底用哪个？别给我三个都买。”

**小陈：**工单 0823 先用固定工作流做内部草稿：查当前工单可见的订单快照，查现行签收争议规则，再写明“已签收”和“客户称未收到”的冲突，交售后看。现在这条路够明确。

**领导：**Agent 先下岗？

**小陈：**先别给它虚构岗位。等回放里真出现一类高频问题：固定分支频繁漏查，但在批准的只读工具里动态补查能解决，我们再把那一小段换成 Agent，并比较答对率、耗时、调用次数和转人工情况。同一批工单比较，才知道多付的钱买到了什么。

**领导：**写进方案。还有一句：“工作流不是低配 Agent”。

**小陈：**这句我替它谢谢您。

**小陈交付的决策卡：**本单采用固定工作流；模型只起草内部回复；查询只读；规则冲突或缺证据直接转售后。验收时，程序必须按预定步骤留下查询和审核记录；如果连固定流程都跑不稳，不以“升级 Agent”掩盖问题。

## 四格流程看似简单，实际藏了三个分岔口

**领导：**我那四个框很清楚，你非说要拆分。到底哪儿会分岔？

**小陈：**先看订单查询：查到、查不到、超时、无权访问，四种结果不能走同一个箭头。再看规则：现行条款明确、两版冲突、文档解析失败，也不能用同一草稿。最后看动作：可写内部摘要、需客服审核的外发、需要业务审批的退款，是不同出口。工作流不是只能走一条直线，它可以有预先写明的分支和状态机。只要这些分支可枚举、后果清楚，让程序决定比让模型临场发挥更稳定。

**领导：**那我的图再加十个菱形，不还是工作流？

**小陈：**是。若十个菱形足以覆盖高频场景，我们就用它。复杂度不是根据图上框数判断，而是看“下一步选择”由固定程序还是模型实时决定。[Anthropic 的官方文章](https://www.anthropic.com/research/building-effective-agents)也作这个区分，并建议先用简单方案，必要时再增加自主性。框多不一定更高级，框少也可能暗藏一个没有边界的模型决策。

**领导：**业务部听到“固定”就说不智能。

**小陈：**客户要的是问题解决，不在乎箭头是谁画的。固定流程能保证每张签收争议单都查订单、看有效规则、交客服审核，遇到缺证据有明确出口。模型仍能在流程中的“整理证据、起草回复”发挥语言能力。把每一步都交给模型选，可能只是给同一条必经路径多付一次推理费，还增加漏查和不一致。真正需要动态判断的地方，让数据说话，再开小范围权限。

## 什么时候一次调用就够了

**领导：**你那张表第一行“一次模型调用”，会不会连 Agent 的边都沾不上？

**小陈：**没关系，需求先于标签。假设客服后台已经把订单状态、客户原话和现行条款查齐，只需生成一段供客服审核的解释。一次调用完成这件事就好，应用校验证据和格式，客服再审核。没有工具选择和持续循环，成本与失败路径都清楚。为了叫 Agent，硬让模型先问“我应该查什么”再查一遍已有事实，等于把已经摆在桌上的材料重新去仓库领一次。

**领导：**一次调用如果答错，工作流不也答错？

**小陈：**对，所以还需评测和校验。架构不能替内容担保。固定工作流能确保来源、版本、对象授权和审核动作按确定路径执行，减少一类错误；模型生成的“可申请”是否说成“已退款”，仍要用业务回执检查。增加 Agent 循环未必修复这个错误，反而可能让它查更多无关资料。先定位错在哪层，再决定需不需要动态工具选择。

## 工作流能分支，Agent 的价值在哪里

**领导：**说了这么多，你总得留个 Agent 能赢的场景。

**小陈：**有。比如客户一封信里同时提到订单 0823 的签收争议、上次客服承诺的补偿和发票抬头。系统不一定能预先用几条规则判断该查哪些证据、按什么顺序处理；模型可在允许的只读工具中识别子问题，按当前证据选择下一步，发现政策冲突时停止。它的价值是动态取证和组织处理，不是自动拥有退款权限。若这种复杂案很少，先转有经验的客服可能更划算。

**领导：**它决定多查一次，是不是就更准？

**小陈：**要有新增信息。已查订单后再查同一订单且状态未变，只增加调用；查客户提到的另一个订单，则可能越权。动态方案应记录每次工具调用的理由、得到的新证据、为何继续或停止。设工具次数、时长与费用上限；无新增信息或出现冲突就交人。模型的自由度越大，越要明确工具范围、对象权限和退出条件。

**领导：**让模型负责决定“要不要退款”，是不是也叫动态选择？

**小陈：**它可以提出建议和引用依据，但正式审批与执行由业务系统控制。是否符合政策可以辅助判断，金额、例外审批与支付结果都要按公司流程。不能把“动态选择下一步”偷换成“动态授予自己权限”。架构图里模型框和业务动作框之间要画校验、审批和回执，不是一根箭头直通财务。

## 用同一张工单算三种方案的账

**领导：**给我一个能用于预算会的比较，别只讲哲学。

**小陈：**把同一批脱敏工单分题型，给三种方案相同的订单与政策版本。一次调用方案由应用预先查齐资料；工作流按固定分支取证；Agent 在受限工具里动态选择。分别记录关键事实错误、漏转人工、无回执承诺、客服改稿时间、客户等待、模型和工具成本。先按红线淘汰危险方案，再看质量增益与成本。若 Agent 在复杂争议题少漏查关键证据，可能值得；若在入口咨询上只是多调用三次工具，不能因为“像 Agent”就全量铺开。

**领导：**简单题占九成，复杂题只有一成。是不是应该全用便宜方案？

**小陈：**可做分流：确定性入口题走模板或固定工作流，复杂且允许动态查证的题进受限 Agent，涉及审批或资金的题转人工。分流器本身要评测，尤其不能把高风险争议误分成低风险自动回复。算总成本时纳入分流误判、客服接手和故障恢复，不只算单次模型价格。即使动态方案单题更贵，若确实减少复杂案的反复人工查询，仍可能划算；结论要靠同题回放和灰度数据。

**领导：**能不能拿一个漂亮 demo 证明 Agent 赢？

**小陈：**不行。一条复杂工单恰好选对工具，不代表它每次能选对；固定流程在这条题上失败，也可能是规则分支没补。评测要覆盖常见题、难题、缺证据、工具超时、规则冲突和客户施压，记录每一步选择。模型多次运行同一题可测稳定性，但不能把三次重复算三种客户场景。报告按题型给出样本量和差异，别用总平均掩盖高风险错。

## 固定流程与动态段，怎样拼起来

**领导：**我要的不是二选一，而是能上线的图。

**小陈：**外围固定：接收工单、验证身份与订单绑定、按业务规则限制工具、筛有效文档、对外发送前审核。中间一小段可动态：模型根据已核实的订单状态和客户问题，在“查签收凭证”“找现行争议条款”“列未知并转人”中选择。动态段每次输出选择理由和引用；执行器核权限，返回受控结果。达到上限或证据不足就停止，不允许模型绕开外围。这样局部复杂度换来可能的取证收益，主流程仍可审计。

**领导：**如果模型选了查签收凭证，但客服系统没这个接口？

**小陈：**工具列表只暴露当前真的可用且获授权的能力。它不能把“希望查询”写成“已查询”。若缺接口，内部卡标缺口、交售后从原系统核实；产品排期再评估是否值得接。不要为了演示让模型调用一个永远返回模拟数据的工具，却在上线报告里写“已自动核实签收”。本期业务事实的真相来源，必须和对客系统一致。

## 出故障时，哪种方案更好收拾

**领导：**订单接口挂了，固定流程和 Agent 谁更能扛？

**小陈：**两者都拿不到当前订单事实。固定流程可按失败分支交客服；Agent 可能尝试其他合法证据，但不能把客户陈述冒充系统状态。谁更好恢复，取决于是否记录状态、工具错误、已查证据和人工接手，而不是名字。动态段若继续循环到费用上限才认输，还更慢。工程上给每种方案同一套故障预算与交接标准，才能公平比较。

**领导：**改政策那天，两种方案会不会一起引用旧版？

**小陈：**会，如果知识库和缓存没更新。有效版本过滤应在检索层，不靠工作流或 Agent 自己分辨封面日期。发布时检查新旧索引，保留历史证据审计，当前对客查询只见现行条款。若新旧冲突，先暂停相关自动结论，交政策负责人。换架构不能替文档治理擦屁股。

## 领导最后的判断题

**领导：**开发问“固定流程分支写到多少条，就该换 Agent”，你给个数。

**小陈：**没有统一数字。看分支变化频率、表达难度和错误代价。十条稳定的售后规则，写成程序更容易测试；三条若要理解客户含糊叙述并动态决定查证顺序，也许需要模型。还要看工具结果是否能被结构化为稳定条件：订单状态、地区和商品类型可直接分支；客户叙述“我明明在家，却显示前台签收”需要语言理解，但理解完仍可进入固定争议流程。先把可确定的留给程序，再把确需解释的局部交模型。

**领导：**如果产品每周加一种问题，写工作流会越长越长。

**小陈：**那要看问题是否共享步骤。可把身份核验、订单查询、规则过滤、审核发送做成复用组件，再给不同问题配置分支；不是每加一题复制整条流程。若新问题确实需要跨资料动态调查，可设受限 Agent 段。架构治理不是在工作流和 Agent 之间选一个宗教，而是避免重复规则、避免无边界自主。每新增题型都写：现有路径覆盖吗，新增工具是什么，权限如何约束，失败怎么回人。

**领导：**Agent 选错了下一步，程序能不能让它“反思一下”？

**小陈：**可给一次有针对性的反馈，例如“该订单不属于当前工单，查询被拒”，让它回到合法路径；但连续试探不同订单号不能靠“反思”放行。若它查了无关资料，记录并停止或转人。重试要有次数、总时长和错误类别，不把每次失败都解释为“再思考就会好”。模型自我反思可能改善答案，也可能只把错误论证得更长；是否有效要看回放。

**领导：**能把复杂题先交 Agent，失败再回固定流程吗？

**小陈：**可以，但回退要明确状态。Agent 已查的有效订单与政策证据带回主流程，不能重复查询却又丢失错误；已失败的工具标未知；任何已提交写动作需查回执。固定流程接手后按自己的条件判断，不无条件相信 Agent 给的总结。反过来，固定流程发现无法预先覆盖的争议再转动态段，也要传当前证据与剩余预算。两个路径通过标准交接卡衔接，客户才不会在系统切换中反复讲同一件事。

**领导：**这套混合方案谁负责线上事故？

**小陈：**给每层明确负责人：业务规则与适用范围归政策方，工具权限与执行归服务端，模型提示和动态选择归 Agent 团队，客服审核与客户沟通归运营。运行轨迹要能定位第一处错误。若 Agent 选错工具但后端拒绝，是模型路径需改；若后端接受他单查询，是授权缺陷；若证据正确却草稿承诺退款，是生成和外发校验问题。责任界面清楚，事故时先止损，再由相应层修复，不靠一句“AI 不稳定”结束复盘。

**领导：**发布时先开多少流量？

**小陈：**先内部影子运行：同一工单由固定流程处理，动态段只生成建议，不碰客户；对照缺失证据、额外调用和客服判断。随后在经选择的低风险题型小流量试点，所有对外内容仍经审核。监控越界请求、漏转人工、生成耗时、工具成本和人工改稿。红线触发可关动态段，固定流程继续；开关要按题型和能力拆，不能回退时整个客服系统一起瘫。试点扩大依赖数据和客服容量，不是领导看完一场演示后的心情。

**领导：**面试官说“Agent 比工作流灵活”，你能不能用一句具体话解释灵活的代价？

**小陈：**在 0823 这单，模型可根据签收争议临时决定补查凭证，这是灵活；它也可能无意义地重复查单、漏看现行规则，或在错误资料里找出一个看似合理的结论。每多一项动态选择，就多一项需要记录、评测和设上限的行为。若业务路径早已清楚，程序分支把风险锁在看得见的地方；只有新增的动态调查确实减少错答和人工返工，我们才用额外成本买它。

**领导：**下一步全能写成条件分支，还需 Agent 吗？

**小陈：**通常先用工作流。若动态选择不能带来可衡量收益，没必要引入额外成本与不确定性。

**领导：**模型在工作流里写回复，工作流是不是就变 Agent？

**小陈：**不是。模型负责某一步文字或判断，整体路径仍由程序预定。关键看谁在运行时决定流程和工具。

**领导：**Agent 能动态选工具，是否也能动态改权限？

**小陈：**不能。工具权限、对象授权、审批和发送闸口由应用与业务系统执行。

**领导：**本单最终用什么？

**小陈：**先用固定工作流处理 0823，模型负责内部草稿；把复杂案留作动态段的对照试点。若它真能在合法只读工具里少漏证据、少让客服返工，再给它方向盘的一小截。公司不用先买一个“万能司机”，才有资格把客户送到目的地。

**领导：**那架构评审的签字项呢？

**小陈：**写清动态段在哪儿开始、在哪儿结束、能见哪些工具、每次如何授权、失败交给谁，以及它比固定流程实际多解决了哪类工单。答不上最后一项，就先不要扩大自主范围。

**领导：**这回方向盘是谁握着，总算说清了。

**小陈：**还要看刹车在哪儿：工具按本单授权，预算到了退出，证据不足转人，对客和退款走审批。动态段若选错方向，外围仍能把客户与公司留在路上。

**领导：**明天评审如果有人说“把全部流程都交模型更灵活”，我就请他先标出哪些分支真的没法预写，再拿同一批工单证明动态选择能少漏查、少返工。拿不出证据，四格流程先踏实跑。

**小陈：**这次先按证据办。
