**领导：**昨天客服已经核过签收记录，今天 Agent 又问客户“您有订单号吗”。不是说它有记忆？

**小陈：**“有记忆”这四个字，比“稍后处理”还容易让人误会。我们缺的是这张工单的交接记录，不是让模型把所有聊天永远背下来。

**领导：**那就把整段对话存着，下次全喂进去。

**小陈：**整段太长，还可能带地址、手机号；换了客户要是拿错线程，就成了大型认亲现场。我给 0823 号工单写一页交接簿：

| 栏目 | 这单写什么 | 谁能改 |
| --- | --- | --- |
| 已核实事实 | 订单归属已核验；签收系统返回“已签收”，查询时间 16:02 | 订单工具写入，客服可标注异议 |
| 未解决的问题 | 客户称未收到；签收凭证尚待人工核查 | 客服／审核流程 |
| 当前状态 | 等待物流核查；未批准退款，未向客户承诺退款 | 工单状态机 |
| 下一步与责任人 | 客服小陈跟进物流回执，截止下班前 | 工单负责人 |

**领导：**对话摘要呢？

**小陈：**只保留对处理有用的事实和客户诉求，不把模型的猜测写成“已核实”。摘要由当前工单 ID 绑定；跨天恢复时先读工单状态，再读摘要；有冲突以业务系统和最新人工记录为准。长期知识库只放可复用的现行政策，不存某位客户的私事。[LangGraph 的持久化文档](https://docs.langchain.com/oss/python/langgraph/persistence)说明了按线程保存检查点的技术机制；业务上仍要自己定工单归属、访问控制和过期规则。

**领导：**怎么证明没串单？

**小陈：**做两次回放：重新打开 0823，Agent 应接着“等物流核查”处理，不再索要已核验的订单号；切到另一位客户的工单，任何 0823 的摘要、订单状态和附件都读不到。工单关闭后，工作记忆按批准的期限清理；若有人重新开单，只能通过授权的工单关联查到必要历史，不能靠模糊相似度捞别人的记录。验收记录把访问失败也记下来，这比一句“模型应该不会”值钱。
