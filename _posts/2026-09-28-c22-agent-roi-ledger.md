**领导：**Agent 三秒出草稿，客服原来要八分钟。我们是不是省了一个人？

**小陈：**三秒是机器写字，不是客户问题解决。客服还要看订单回执、核政策、改草稿、批准发送；转人工的单可能比原来更难。要谈省人，先把一张单从进来到结案的人工时间算全。

领导指着演示记录：“你看，三秒。”小陈把记录往下翻：草稿在第三秒出现，客服第六分钟才发现它引用旧规则，改完后又查了一次订单。**演示视频截在三秒，工资表不会。**

## 用同一批工单，算“人工实际碰了多久”

**小陈：**先挑一个边界清楚的试点群：例如发票入口、发票状态、签收争议三类，不把完全不同的咨询混成平均数。取上线前后相近时段的工单，标记渠道、复杂度、规则版本和班次；试点期间保留有人审核。每张单记录：人工阅读与查证、草稿审核修改、转人工接手、返工、后续复联。模型费用、运维、知识维护和事故补救另列，不藏进“生成耗时”。

| 账目 | 要从哪里取 | 容易漏掉的部分 |
| --- | --- | --- |
| 人工基线 | 旧流程同类工单的触碰时长与结案时长 | 复杂单被排除后的样本偏差 |
| 试点人工 | 审核、修改、接手、补充查证 | “看一眼就过”的碎片时间 |
| 运行成本 | 模型、检索、工具、日志与部署账单 | 超时重试、空跑、缓存失效 |
| 维护成本 | 规则更新、样本标注、告警值班 | 一次更新波及多个版本 |
| 质量代价 | 错答纠正、投诉、重复联系 | 客户换渠道回来，原单没算返工 |

**领导：**给个数，别只让我看字段名。

**小陈：**下面是**纯演示算例，不是我们博客或任何公司的实测成绩**。假设一个月有 1,000 张同类单，旧流程平均人工触碰 8 分钟；试点后每单审核、修订与接手合计 4.5 分钟，看上去省下 `1,000 × (8 - 4.5) = 3,500` 分钟，也就是约 58 小时。但如果一个月还要花 40 小时维护规则与样本、12 小时处理错答和复联，净减的人工触碰只有约 6 小时。再扣技术账单，显然不能写“省了一个客服”。

再做一次敏感性检查。假设复杂工单占比从试点时的 20% 涨到 40%，需要人工二次核对的单随之增加，那个 4.5 分钟均值很可能上升；假设新政策每周变一次，40 小时维护也可能翻倍。平均值一改，结论就变。因此试点表不只填一行总均值，还要分别列简单题、争议题、系统故障题的人力触碰时间与样本量，报告中给出范围和假设。用一小段顺利演示推全年编制，算式再漂亮也站不住。

再给财务看一个**同样虚构**的货币换算：如果这约 6 小时 20 分的净人工时间按每小时 60 元的内部核算口径折算，约是 380 元；若当月模型、检索和部署增量为 300 元，账面净值只剩约 80 元，而且还没计入培训与项目启动成本。这个数字不用于决定裁员，恰恰说明为什么要把参数写出来：人工时薪、单量、维护小时或技术成本任一变化，结论就可能翻转。财务可以替换成公司的真实口径重算，而不是接受一句“省了一个人”。

**领导：**那 Agent 不就白做了？

**小陈：**也不一定。它可能让客服把精力从入口问答挪到签收争议，可能缩短客户等待，可能减少漏答；这些都要单列质量和体验指标。我们还要看高峰时是否更稳，而不是只看月均。比较时用同类工单和相同观察窗口，若试点接入后刚好碰上促销或新政策，不能把业务波动全记在 Agent 头上。

## 决策写成三道门，而不是一句“有潜力”

**小陈：**继续试点的条件：高风险错误为零或低于事先批准的门槛，复联率不升，客服净触碰时间有可信下降，技术与维护支出在预算内。若简单题有效、争议题返工严重，就**收窄范围**，只保留发票入口这类固定流程；若错误承诺、跨客户访问或补救负担持续出现，就**暂停外发能力**，先修系统。门槛由业务负责人在试点前签字，不能看完结果再改分数线。

为了避免“AI 组挑简单题、人工组接烫手山芋”，两组工单要按类型、风险和时段对齐；若不能随机分配，至少记录差异并在结论中说明。计时从工单入队开始，到达到同一种结案标准结束；不要一边算 Agent 草稿出现时间，一边算人工最终处理时间。管理者还应看高峰时的队列积压：月均节约六小时，若每逢大促都要加班救火，排班价值仍可能为负。

## 先分清三种“快”：生成快、坐席省时、客户早点解决

**领导：**我看报表里还有“平均处理时长”，拿它当总收益行不行？

**小陈：**先看定义。Agent 三秒生成草稿，是**机器响应时长**；坐席从打开工单到完成审核累计花四分钟，是**人工触碰时间**；客户从第一次求助到问题有明确结果等了两天，是**端到端解决时长**。三者可以同时变好，也可以一个变好、另两个变坏。签收争议的草稿再快，物流仍需核查；如果 Agent 草稿频繁错引，坐席审核时间反而增长。我们必须按业务目标分别量，不让最快的那个数字代替全部。

人工触碰时间也不等于登录客服系统的墙上时钟。一位坐席在 09:00 查订单两分钟、09:30 审草稿一分钟、次日核物流三分钟，累计触碰六分钟，端到端却超过一天。若客服开着工单窗口去参加会议，不能把整段空闲算进处理；若同时看三张单，也不能把同一段时间各记三次。系统可用开始/结束操作、状态变更和抽样观察估算，但计时规则要公开，抽样核对实际工作。没有完美自动计时，也比随手把“生成耗时”当“节省人力”强。

**领导：**那是不是只看人工触碰最公平？

**小陈：**还不够。假设平均每单只省一分钟，但高峰时准确分流让待办不积压，客户等待明显下降，业务可能愿意付费；反过来，平均省三分钟，少数高风险错答导致大量投诉，也可能不值得。人工、客户体验、质量风险和运行成本是四个并列维度。最终是否扩量取决于公司实际目标和事先批准的红线，不是从某一列推出来的万能 ROI。

## 试点怎么设计，才不会“简单题归 AI，难题归人工”

小陈在试点表里先固定入组标准：同样的渠道、同样的三类问题、同一段政策生效期；再记录订单工具是否可用、客户是否重复联系、是否需要人工审批。理想情况下随机把适用工单分到当前流程和 Agent 辅助流程，两个队列的客服班次和服务承诺一致。若业务上不能随机，至少按问题类型、风险、渠道、班次和历史复联次数分层匹配，并明说仍可能有未观察到的差异。不能让 AI 组全是“发票入口在哪”，人工组全是“签收争议要退款”，然后用总体均值宣布自动化胜利。

**领导：**客户体验会不会因为试验分组不一样？

**小陈：**外部承诺保持一致，试点初期所有对外答复仍由客服审核。这样比较的是“Agent 帮坐席查证和起草是否有效”，不是拿客户冒险试无人值守。工单入组时记录实验组，运行中即使失败转人工，也留在原组统计，不能把难题转出去后从 Agent 分母里删掉。质量抽查的人最好看不到分组标签，先按同一标准判断证据和结论，再分析差异。试验前把停止条件写好：跨客户访问或未经批准外发直接暂停；其他错误按风险等级设阈值，而不是看见好结果才修改规则。

观察期要覆盖知识更新和班次变化。只在某个熟悉系统的白班坐席中跑一周，结果可能是“这几个人会审草稿”，不代表晚班、兼职坐席也能用。报告分开写新手和熟手的审核时间，记录培训工时；上线后客服人员变动，这笔成本会持续发生。模型或规则版本改动，也要标记在样本上，不能把不同版本的表现揉成一个月平均数。

## 成本公式：一张单省几分钟，能否覆盖固定支出

**小陈：**把月度净收益写成一行可替换参数的式子：

```text
月度净价值
= 适用工单量 ×（旧人工分钟 - 新人工分钟）× 人工每分钟成本
- 模型与工具调用费
- 固定运维、知识维护、标注、培训时间折算
- 经确认的补救与返工成本
```

这不是要把客户体验硬塞进一个虚假的人民币数字。首次解决时长、复联、满意度和严重错误另列成门槛：门槛没过，就算账面净价值为正，也不准扩量。对于偶发但后果严重的错误，简单用“发生次数 × 平均修复分钟”可能低估风险；应列影响范围、最坏可接受情形与止损能力，由业务负责人决定是否能承担。

**领导：**举个盈亏平衡点，别让我靠感觉。

**小陈：**继续沿用本文的**假设数字**：每单节约 3.5 分钟，内部人工折算每分钟 1 元；每单技术成本 0.30 元，月固定维护与补救合计 52 小时，折算 3,120 元。每新增一张适用工单，理论边际净值约 `3.5 - 0.30 = 3.20` 元；覆盖 3,120 元固定成本约需 `3,120 ÷ 3.20 = 975` 张适用工单。一个月只有 500 张时，单价再漂亮也可能不回本；有 5,000 张时，固定成本被摊薄，但队列容量、错答率和系统限流又会成为新约束。数字全是演示，作用是暴露假设，不是预测某家公司利润。

还得看**适用率**。客服每月 10,000 张单，如果只有 8% 属于规则清楚、可查证、可审核的试点范围，真正能乘进公式的是 800 张，不是 10,000 张。若为了提高适用率，把高风险争议也一股脑交给 Agent，审核和返工可能陡增。价值曲线不会永远线性，扩量后常常先遇到更难的问题，边际收益下降。报表里既给“全量工单数”，也给“符合准入条件的工单数”和“实际成功处理数”。

## 错答与故障怎么入账，才不会把损失藏在别的部门

**领导：**客服补救本来就要做，为什么全部算 Agent 的成本？

**小陈：**不应全部算。要比较**增量**：旧流程也会错，试点新增或减少了多少错。每个补救案例归因到证据过期、工具故障、草稿误判、审核漏看或客户新信息，并记录旧流程在相同类型上的基线。若事故主要来自订单系统故障，不能把锅全扣模型；但如果 Agent 在接口超时后编造物流，自动化方案就该承担由此新增的纠正和投诉处理成本。归因不清时先标未知，不把它塞进“其他”就当零。

小陈还提醒领导看成本转移。技术团队维护提示和知识库的工时，原来不在客服预算；法务或隐私团队审查数据流，原来不在工单报表；客服班长每天复核异常，可能没有被个人处理时长记录。若一个部门的 KPI 变好、另两个部门加班，集团总账未必变好。试点里给每项工作指定记录人和时间口径，月末由三方一起核对，而不是各自拿有利的一页截图开会。

故障成本也有两类：一类是能计数的，例如补发更正消息、人工回访和调查工时；另一类是难精确货币化却必须守住的，例如跨客户泄露或错误退款承诺。这类列为**硬红线**和事故响应要求，不因“预计概率很低”就折成几毛钱。业务决策可接受的不是数学上永远零风险，而是权限边界明确、错误可发现、可暂停、可追溯、有人补救。

## 领导临时出的五道“面试题”

**领导：**第一题，AHT 下降就代表效率提升吗？

**小陈：**不代表。AHT 等处理时长指标若只统计当前一次接触，客户之后复联、投诉或跨渠道重开就被遗漏。要同时看同案复联、完整解决时长与质量错误，并统一问题类型和观察窗口。时长下降可能是把难题提前转走，也可能是真优化，必须拆分来源。

**领导：**第二题，固定成本和边际成本怎么区分？

**小陈：**模型调用随工单量变化，通常更接近边际成本；部署、评测集维护、知识负责人和培训通常有固定或阶梯式部分。扩量时先看每单净节约能否覆盖月固定成本，再看并发增长是否带来新增值班、机器或审核席位。不能只拿单次模型价格乘工单量。

**领导：**第三题，为什么不能用节约分钟直接换算裁掉几个人？

**小陈：**工时分散在班次、峰值和不同技能岗位里。月均节约 60 小时不等于每天都能少一个完整班次；复杂单仍需熟练客服，事故也要有人兜底。要先看排班容量、服务时限和任务再分配，再讨论人员结构。

**领导：**第四题，试点里 Agent 失败转人工的单算哪组？

**小陈：**仍算原来的 Agent 试点组，并记录转人后的全程人工时间。否则最难的单一失败就从分母消失，指标会被人为抬高。这叫按入组口径分析，便于比较方案整体效果。

**领导：**第五题，什么情况下应该收窄而不是停掉整个项目？

**小陈：**如果固定入口题稳定减少重复劳动，高风险争议题却审核负担大，就收窄到入口题并继续人工审核；如果发生跨客户取数、未经批准外发等边界失败，则先暂停相关能力，修权限和发送闸口。收窄是根据分层数据保留有效场景，暂停是因为风险边界已破，两种决策不能混叫“再优化看看”。

## 让计算能复核：一张工单最少留下哪些时间点

小陈给数据同事一份事件清单：工单创建、首次分配、Agent 开始与结束、草稿进入审核、客服打开审核页、客服批准或退回、消息送达、转人工申请、具体客服接手、结案、客户再次联系。每个时间点带 `ticket_id`、问题类型、风险档位、渠道、发布版本和操作者类别。人工实际触碰时间若由操作日志估算，要标估算规则与缺失比例；不能在报表里把没有记录的时间默认成零。故障处理工时和知识维护工时也用任务号关联到月份，至少能回查为什么这个月突然多了二十小时。

**领导：**客服会不会觉得又多填一堆表？

**小陈：**尽量用系统事件自动采集，人工只标关键归因，例如“草稿错引规则”“订单接口不可用”“客户新增信息”。一页表单如果要坐席手写十分钟，ROI 研究本身就会把收益吃掉。先抽样观察一小批工单，校准自动计时与真实操作的偏差；只有足够可靠的字段才进正式报表。对于无法自动衡量的工作，用定期抽样而非让所有人永久填流水账。

月报样式也定下来：先给适用工单量、实验组与基线组构成；再给每类的人工触碰 p50/p95、端到端解决时长、复联和严重错误；第三页才是技术费、维护费、补救费与净值算式。每个总数字都能钻到一组脱敏工单。若本月模型换版或政策变更，报表把事件日期标出来，不能把一段突变藏在月均线里。

**领导：**我要一个今天就能签的结论。

**小陈：**签“继续有人审核的小范围试点，并按上述口径补齐记录”，不是签“省一个客服”。若下一轮连续稳定地降低同类单的人力触碰，客户复联与高风险错误不升，且覆盖固定与边际成本，再扩大低风险范围；若只是草稿快、审核和补救更慢，就回到固定流程或人工处理。决策条件写在试点开始前，月底谁都不能临时改公式给自己找赢面。

领导又问：“如果省下来的时间没有变成现金，还算收益吗？”小陈说：“算，但要写对名字。坐席能把同一班次空出来的零碎时间用于复杂投诉，叫容量与服务质量改善；只有排班或外包支出实际变化，才叫现金成本下降。两种收益都可以重要，但不能在报表里重复计算：一边把节约分钟折成人工费，一边又把同一段时间创造的处理能力当第二笔现金收入。”财务与客服一起确认口径，避免一个项目在两张表里各赢一次。报告还要注明工作量上限：如果被释放的时间集中在凌晨低峰，而投诉高峰发生在下午，纸面总小时数相同，也未必能补上最缺人的班次。排班模拟要按小时查看进入队列的工单和可用坐席，而不只按月汇总。

**领导：**那人力结论怎么写？

**小陈：**写“尚不能据此减少编制”。等连续几个周期的数据、峰值表现和服务质量都稳定，再讨论岗位安排。客服减少重复点按钮，可能转去处理复杂案，这也是收益；不能把一个三秒草稿直接换算成一个人的饭碗。

**领导：**项目周报说客服每单省两分钟，为什么总账仍亏？

**小陈：**看这两分钟是草稿生成阶段省的，还是客户问题真正解决前省的；人工审核、重大改稿、系统维护、模型调用、客户复联和错误补救都要计入。简单工单提效可能被少数复杂投诉的处理成本吃掉。用同类工单作对照，标注样本量和排班变化，别把一次演示的节省时间乘全年单量当收益。
