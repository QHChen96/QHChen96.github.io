**领导：**账单上这类简单问题，一问竟能烧到三块钱。模型又涨价了？

**小陈：**先别给模型定罪。我们把“发票入口在哪”送进了复杂查证路线：模型规划两次、检索三次、查单一次、失败重试一次，最后还让大模型润色两轮。像去楼下买瓶水，先叫了辆搬家车。

**领导：**那换便宜模型。

**小陈：**先拆账。每张工单记调用次数、输入输出 token、缓存命中、检索次数、工具等待、重试次数、技术费用，以及用户看到首条有效答复的时间。费用用调用时的实际计价与用量核算；不在文章里写一个会过期的模型单价。[OpenAI 的延迟优化指南](https://developers.openai.com/api/docs/guides/latency-optimization)也把减少请求、减少 token 和并行化等作为不同的优化手段。

**领导：**给一张看得懂的对照表。

**小陈：**下面是**演示数据**，只示范算法，不冒充我们的线上实测：

| 同一类工单 | 模型调用 | 检索／工具 | 技术费用 | 响应时间 |
| --- | ---: | ---: | ---: | ---: |
| 原路线 | 8 次 | 3／1 次 | 3.00 元 | 19 秒 |
| 固定发票流程 | 1 次或无需模型 | 1／0 次 | 0.18 元 | 3 秒 |

**小陈：**优化顺序是：先把固定入口题移到确定性流程；常用且版本稳定的帮助页做带版本号的缓存；查证型工单限制步骤和重试；低风险分类或摘要可评估更轻的模型。缓存命中也必须受规则版本控制，新政策发布就失效，不能为了省钱重演旧规则事故。大段重复上下文如适用，可评估供应商的提示缓存，但先核对计费、保留和数据要求。

**领导：**省钱后答错了算谁的？

**小陈：**对照必须用同一批工单：除了每单平均成本，还看 p50、p95 响应时间、错引规则、越权调用、漏转人工和返工率。任何红线变差，优化方案回退。单次技术账算清以后，再把人工审核和维护成本并入总账；今天不能用“模型便宜了”替代“整个客服流程划算了”。

## 三块钱不是一个价格，是八轮决定的总账

**领导：**你说把账摊开。三块钱怎么查出是谁花的？

**小陈：**先让每个工单有统一 `case_id`，每次模型调用、检索、工具请求和重试都挂在这张单下。模型调用记录模型标识、输入输出用量、缓存命中与当时计价版本；检索记录查询次数和索引服务费用；工具记录调用次数、耗时与可能的外部计费；人工审核记录实际接触时长；客户复联则回到原问题，不另算一张“新客流量”。财务账单给出总金额，运行轨迹解释它花在哪一步。两者要对账，不能只看一条模型 API 请求的估算值。

这张虚构发票入口单的八轮里，第一轮分类，第二轮计划，第三轮检索，第四轮复述检索结果，第五轮查订单，第六轮因超时重试，第七轮写答复，第八轮润色。真正必要的事实是“当前 App 的下载入口”，一次有效帮助页查询就够。最昂贵的不是某个模型突然涨价，而是**错误路由把简单题送进复杂路径**。先去掉没必要的轮次，再考虑每轮用哪个模型；不然把搬家车换成便宜搬家车，楼下买水还是很慢。

**领导：**那账单里 token 和钱怎么换算？

**小陈：**按每次调用的输入、输出、缓存计费类别，乘以当时供应商对该模型与功能的实际价格，再加工具、检索和运行成本。若同一工单混用多个模型，各按各的费率；若供应商在月中调价，必须按调用时点或账单口径核。文章中的 3.00 元与 0.18 元只是演示数，不是任何产品报价。还要区分“本次模型请求收费”和“整张工单处理成本”：客服改稿、投诉返工、系统维护与审核排班不在模型账单里，却真由公司付。

如果模型调用被取消或超时，是否计费要看服务端实际处理和供应商账单，不能凭客户端报错归零。缓存命中也不是白送，具体命中条件和计费按供应商规则查；我们可以用可观测数据核账，不在产品文案里写“缓存省 90%”这种没验证的数字。成本仪表盘要能从总额下钻到工单与调用，保护客户内容，不把手机号当账单标签。

## 延迟要量客户等多久，不是只量模型吐字快不快

**领导：**模型请求只花两秒，客户却等十九秒。其余时间去哪了？

**小陈：**看关键路径。入口网关排队、检索索引响应、订单工具等待、模型连续八轮、人工审批、发送渠道确认都可能占时间。串行步骤的耗时会相加；独立只读步骤若并行，整体等待近似看其中最慢者再加合并成本。测 `time_to_first_usable_answer`，即客户首次得到可执行且正确的回复，不要把流式输出第一字的时间当解决时间。机器人零点五秒开始说“好的，我来看看”，最后十八秒才给入口，客户仍等了十八秒。

把每张单的时间线画出来：分类 0.4 秒、模型规划 1.2 秒、三次检索合计 3 秒、订单工具及重试 8 秒、草稿和润色 4 秒、其余排队与发送 2.4 秒，合计约 19 秒。这组数字同样是演示，用来说明如何找瓶颈。若瓶颈在订单工具，换更快的模型未必让客户明显更快；若多余轮次占大头，去掉一轮比调 token 上限更直接。

**领导：**那把所有工具并行叫起来，十九秒不就变五秒？

**小陈：**只有独立且必要的工具才值得并行。发票入口题根本不需要查订单，先删这次查询；查证题若订单状态和政策条款可独立读取，可以并行；退款审批必须等事实和权限确认，不能为追速度提前并行提交。并行会增加瞬时负载，也可能让取消和错误处理更复杂。优化关键路径，不等于所有按钮一起按。OpenAI 的延迟优化指南也把减少请求、减少 token、并行化区分为不同手段，选哪个应看实际轨迹。

## 缓存不是省钱魔法，先写“何时失效”

**领导：**发票入口天天有人问，缓存答案，一毛钱都不用花。

**小陈：**可以缓存**稳定的帮助页事实**，但键要包含渠道、客户端版本、地区或客户类型等影响入口的条件，以及知识条目版本。政策或页面变更时要主动失效，不能只设“缓存一天”。发票入口从“订单详情”改到“服务中心”后，旧缓存可能省了三块钱，却让几百位客户找不到入口。缓存命中后仍检查条目处于生效状态；规则负责人能追到哪次发布让缓存刷新。

不要缓存具体客户的订单状态当通用答案。订单状态是按人、按单、按时间变化的事实，跨客户缓存会出严重事故；即使只给同一客户用，也要限制陈旧度并显示查询时间。模型提示缓存保存的是可重复的输入前缀等技术材料，和业务知识缓存不是一回事；前者是否适合含客户信息、如何计费与保留要看供应商规则，后者要解决版本和适用范围。两种缓存都叫“缓存”，但省钱的前提和泄漏风险完全不同。

**领导：**那用小模型先答，答不好再用大模型，能省吗？

**小陈：**可能，但要把升级判断算进去。低风险入口分类可由规则或轻量模型处理；复杂争议再用更强模型加工具查证。若小模型经常误判复杂题为简单题，省下的 API 费会被错误承诺吞掉。评估要看每类题的路由准确率、人工改稿、复联和高风险错误，而不是只看小模型平均单价。先确认任务需不需要模型，再选模型规格；不必把所有发票入口都交给“聪明但爱巡山”的大型 Agent。

## 账本上少了人工，ROI 就会像魔术

**领导：**固定流程从三块降到一毛八，是否可以宣布节省 94%？

**小陈：**只能说在这组虚构演示数据里，**技术调用费用**下降了这个量级，不能推出整个客服成本下降。若固定流程让客服改稿从零变成每单两分钟，人工费用可能远超模型费；若入口答错导致客户三次复联，工单总成本反而上升。成本决策要按独立问题或工单归集：技术费、人工接触时间、审核、维护、故障补救、客户复联。不同问题类型分开算，别让发票入口的省钱掩盖退款争议的处理负担。

对照实验要让两组面对相同问题分布、相同生效规则和相近的渠道时段。简单单全部给固定流程，难单全部给旧 Agent，再拿平均费用比，结果一定偏。可以先用同一批历史工单离线回放，再小范围灰度，记录每个题型的成本和质量。优化前写好不可突破的护栏：错引旧规则、越权调用、漏转人工、错误承诺不得增加。便宜不是客服目标，**正确解决且客户不必回来骂第二次**才是。

**领导：**如果技术费用省了，p95 延迟却变慢呢？

**小陈：**看客户是否感知与服务承诺。平均耗时可能被大量简单题拉低，少数复杂客户等得更久；p95 能提示尾部，但仍要按题型和渠道看。缓存失效时的冷启动、系统限流时的排队、人工队列的等待都要入账。若省钱方案把最困难的客户推到漫长等待，不能只报每单平均省两元。优化方案可以按路径部署，低风险入口走快路，高风险争议保留更完整的查证与人工保障。

## 领导拿四张账单考小陈

**领导：**第一张，模型费降了，工具调用费涨了。算优化成功？

**小陈：**按整张单的技术成本和质量算，不能只看模型行。还要查工具调用是不是必要，是否增加延迟与权限风险。

**领导：**第二张，token 降了一半，错答也多了一倍。

**小陈：**先回退或收窄到安全题型。省 token 是手段，事实正确与权限红线是门槛。尤其不能靠删掉规则条件来压输入长度。

**领导：**第三张，缓存命中 90%，客户仍说入口不对。

**小陈：**查版本键和失效回执。命中率高可能只是高效地重复旧答案；正确命中生效且适用的知识才有价值。

**领导：**第四张，API 账单下降，客服说更忙了。

**小陈：**把人工改稿、二次联系和审核时间并进工单成本，再对照同类工单。财务看到的是一部分账，客服感到的是另一部分；把账合上，才能决定要不要扩大。

**领导：**所以三块钱的罪魁祸首是谁？

**小陈：**不是某个模型的名字，是我们让一个发票入口题跑了八轮不必要的路线。修路由、删多余调用、按版本缓存、保留质量护栏，比对着价目表骂模型更有效。

## 把 3.00 元拆成一张能核算的演示账

**领导：**给我看一次加法，别只说“综合成本”。

**小陈：**下面这笔钱完全是虚构演示，不代表任何真实模型或供应商报价：八次模型调用合计 2.40 元，三次检索及索引服务分摊 0.30 元，订单工具与失败重试分摊 0.20 元，运行与监控分摊 0.10 元，**技术费用合计 3.00 元**，与上表口径一致；客服审核按本单实际接触时间另分摊 0.60 元，**全流程成本示意为 3.60 元**。若只看模型 API 账单，会说“一单两块四”；若把客服人工漏掉，还会误以为自动化程度很高。正式账本必须把技术费用与全流程成本分列，不能在同一张汇报里混用。

固定流程的技术账也要同口径比较：帮助页检索、可选的一次轻量模型调用、运行与监控合计示意 0.18 元。若客服仍需审每一单，人工 0.60 元不能突然消失；若低风险入口经验证可自动回复，人工变成抽检与异常处理，也要按真实抽检比例和返工率分摊。由此看出两个阶段的收益不同：**先少走七轮**降低技术费和客户等待，**再有条件地减少人工审核**才可能大幅降低全流程成本。第二步必须过质量与权限门槛，不能因第一步省钱就自动批准。

**领导：**按平均值算，一百张单省两百多元。月报能这样写吗？

**小陈：**要先确认一百张是否都属于同一适用题型。若其中二十张其实是“已付款却开不了票”，固定入口流程不适用，强行推过去会造成漏查与复联。按题型分桶，分别计算旧新路线的单均成本、成功解决率和转人工率，再用线上真实流量加权。还要看节省是否被一次严重错答的补救成本抵消。平均成本可以做预算，风险决策不能只看平均。月报应附样本量、费用口径和异常工单范围，免得“节省 94%”成为另一种 99% 演示。

## 优化顺序由“哪一段最长”决定

**领导：**你能不能给团队一张顺序单，别每次都说“看情况”？

**小陈：**先抓运行轨迹，按题型找最大耗时与费用来源。若多数入口题都被误路由，先修分类和固定流程；若查证题重复检索同一文档，改检索策略和停止条件；若模型输入反复塞全量历史对话，做按需上下文与摘要，但关键承诺不删；若工具等待占大头，查接口和重试套娃；若客服审核占大头，先提高草稿可用率和证据可见性，再讨论自动外发范围。这个顺序不是一张永久排行榜，而是让每次优化对准实际瓶颈。

每改一处都跑同一批回放与小流量对照：技术费、全流程成本、首次有效答复时间、p95、事实错误、人工改稿、客户复联和越权事件。最好一次只改一个主要变量，不要同时换模型、换知识库、换路由又改话术，结果变好或变坏都查不出原因。发布记录写清版本和回退开关，成本优化也属于生产变更。

**领导：**如果缓存和小模型都让成本更低，该先上哪个？

**小陈：**看证据与风险。当前帮助页稳定、适用范围清楚，按版本缓存事实可能直接减少重复检索；小模型替代大模型需要同题评测，证明路由与回答质量守住。两者也可以组合，但先分别测，确认增益。缓存命中率和模型单价都不是最终目标，目标是同类客户得到正确指引所花的总成本与时间。

## 排队时间和客户时间，账单上常常没有

**小陈：**还有一项容易漏：流量高峰的排队。账单只记模型真正执行了多少 token，客户却可能在限流队列等十秒。技术指标要把排队、工具等待、人工接手和渠道送达拆开；按分钟看流量峰值与并发，不能只用月平均单价计划容量。若固定流程把入口题从昂贵路线移走，还能释放复杂争议题的模型并发，这种收益可能体现在高风险客户的等待时间下降，不直接出现在单张发票账单里。

**领导：**那能不能用流式输出，让客户觉得快一点？

**小陈：**流式输出能更早显示文字，但不能让错误事实变正确，也不能缩短后台工具等待。可以先给准确的受理确认，同时后台查证；别在证据没到前流出“您的发票已经……”这种半句话。若答案必须等订单状态，第一字再快也不能越过事实。量“首次有用且正确的内容到达时间”和最终解决时间，才知道流式体验是否真正帮了客户。

小陈最后让财务、客服和研发看同一张工单的三行数：技术费用、全流程成本、客户从提问到得到正确入口的时间。技术费用从 3.00 元降到 0.18 元，只有在同类问题上质量不降、人工没有偷偷增加时，才可能变成公司真实节省；客户时间从 19 秒降到 3 秒，也要确认不是因为系统省略了该查的证据。每个数字旁边写样本量、题型、时间窗和版本，别把虚构演示数据贴进季度业绩。

**领导：**那“便宜模型”究竟什么时候换？

**小陈：**等我们知道哪些题根本不需要模型、哪些题要有限查证、哪些题必须交人之后。对需要模型的那部分，用同题样本比较候选模型的质量、延迟、费用和失败恢复；通过红线再灰度。若轻量模型只负责分类，客服真正关心的是错路率和纠偏能力；若它负责对客回答，还要看证据引用和错误承诺。名字便宜，不代表整张单便宜。

账单上的三块钱最后成了一个改路由的工单，而不是一场模型价格谈判。领导仍然爱问“还能再省点吗”，小陈现在会先把客户有没有拿到正确入口的那一栏打开，再谈下一毛钱。

这份成本账每次发布后都重算。规则变更可能让缓存频繁失效，流量变化可能让固定流程占比下降，人工审核要求也可能收紧；旧版省钱结论不能自动继承到新版。运营按题型定期复核，技术按轨迹找新增的重复调用，客服把返工时间记回原单。省钱方案只有持续守住服务质量，才值得长期留在生产里。

**领导：**平均每单便宜了三元，高峰时客服却要多等半分钟，这账怎么算？

**小陈：**按题型和高分位延迟拆开看，模型费、检索费、人工审核、复联与超时补救放在同一张单上；退款争议的等待和错承诺成本尤其不能被普通入口题摊薄。若便宜方案让客服多改稿、客户多复联，总成本可能更高。试点数据按同一业务范围和时间窗采，演示算式不直接写进预算。
