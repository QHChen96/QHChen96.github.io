**领导：**我看流程图挺完整：消息进工单系统，n8n 调 Agent，Agent 查订单，客服审核，然后自动回写。怎么客户明明收到了回复，后台还显示“无人处理”？

**小陈：**因为图里全是箭头，没有“谁说了算”。n8n 看到任务成功，是工作流运行成功；Agent 生成了草稿，是查证和起草成功；渠道返回已发送，是一条消息发成功。**这三件事都不等于工单已经解决。**

小陈打开虚构的 0823 号工单。客户说“显示签收，没收到货”。Agent 查到“已签收”，草稿写“我们继续核查签收凭证”。客服批准并发出。n8n 收到成功回执后把流程标成绿色，可工单还需要物流调查。第二天客户追问，队列里却没有责任人。图上漏掉的不是一个节点，是业务上的“谁继续管”。

## 先定唯一的账本，再定每段谁有权动笔

**领导：**把所有状态都放 n8n 不就统一了？

**小陈：**编排工具可以调度，但工单的权威状态仍放在工单系统。原因很实在：客服换班、客户再次来信、审计抽查和人工改派，最后都要在同一张工单上看得到。n8n 可以被替换，工单历史不能跟着消失。

| 组件 | 负责什么 | 不负责什么 |
| --- | --- | --- |
| 工单系统 | 工单 ID、客户关联、责任人、状态、时限、最终结案 | 让模型自己决定业务事实 |
| n8n 或其他编排层 | 接事件、调服务、重试可安全重试的步骤、记录运行关联 | 代替工单系统宣告“已解决” |
| Agent 服务 | 在授权范围内查证、引用规则、生成内部草稿和未决项 | 直接改客户身份、审批、发送或结案 |
| 审批与发送服务 | 绑定草稿、收件人和批准人；发送并记渠道回执 | 猜测业务后续已完成 |
| 客服／物流负责人 | 接下调查、处理例外、确认解决 | 为没有证据的自动答复背书 |

**领导：**接口上怎么保证这些箭头不是“画着好看”？

**小陈：**给每张单一个稳定的 `ticket_id`，每次触发再有 `event_id` 和 `run_id`。工单事件只带必要字段：事件类型、工单版本、渠道、授权范围和关联 ID；客户原文由有权限的服务按需读取，别把地址复制进每个 Webhook。下游写回要带工单版本：如果客服在 Agent 思考时已改派或结案，旧运行的写回要被拒绝并进入冲突队列，不能覆盖人的更新。

接口契约可以长这样。这里的 ID 与版本是示例，重点是**事件唯一、业务版本明确、敏感内容不随事件广播**：

```json
{
  "event_id": "evt-0823-04",
  "event_type": "ticket.evidence_requested",
  "ticket_id": "0823",
  "ticket_version": 7,
  "run_id": "run-9f2",
  "channel": "app",
  "allowed_tools": ["read_current_order", "read_active_policy"]
}
```

编排层接到事件，先用 `event_id` 去重；调用 Agent 时把授权范围从服务端带过去，而不是让 Agent 自己根据客户原话决定能看什么。Agent 返回的是**提议**，工单系统检查 `ticket_version` 仍为 7 才能写草稿。若客服此时已把工单推进版本 8，编排层把冲突放进待核队列，不能悄悄用旧证据覆盖新处理。发布到生产前还要演练“工作流重启后重放同一事件”，看它会不会重复建子任务。

一次正常流转是这样：工单系统发“待查证”事件；编排层接到事件后去重并调用 Agent；Agent 返回**证据引用、草稿、未决项**；工单系统保存内部草稿；客服审批；发送服务核对批准版本后外发；渠道回执回写“已回复”；工单仍归物流核查负责人，直到有签收调查结果和客户问题的处理结论，才能走结案审核。

**领导：**万一 n8n 那段掉了？

**小陈：**掉了也不能丢单。事件写入工单侧待处理表，编排成功与否另记运行状态；超时进入有主的重试或人工队列。重放同一 `event_id` 不再多发一条消息；若发送结果未知，先查渠道回执。[n8n 官方文档](https://docs.n8n.io/build/flow-logic/handle-errors-gracefully)提供错误处理和错误工作流能力，但业务去重、工单所有权和“已回复不等于已解决”的规则要我们自己实现。

领导问：“n8n 的执行记录不是也能查吗？”小陈把两个记录并排放：n8n 记录“节点 6 成功”，工单记录“物流还未回执、客服小陈负责”。前者帮助工程师定位哪一步断了，后者告诉业务下一步该找谁。运行记录清理或更换编排产品，不应清掉工单的待办。反过来，工单只写“失败”也不够排障，要能从工单关联 ID 点回那次运行的错误节点与重试次数。

## 交给领导的不是四张截图，是一条闭合链

**小陈：**上线验收用一张工单跑四次：正常回复后保留物流负责人；编排中途失败后待办仍在；客服抢先改派时旧运行不能覆盖；客户再次回复能回到原单且看到上次查证。每次都从工单系统点开：谁负责、谁批准、发了什么、还欠什么。若客服必须在四个后台拼图，这套集成还没做完。

**领导：**所以 n8n 该不该用？

**小陈：**可用来编排重复步骤和接异构系统，[Webhook](https://docs.n8n.io/integrations/builtin/core-nodes/n8n-nodes-base.webhook)和[错误处理](https://docs.n8n.io/build/flow-logic/handle-errors-gracefully)都有官方说明。它不该成为唯一业务账本。今天先把责任表和接口契约定下，再换哪款编排工具都不会把工单主人换没了。
