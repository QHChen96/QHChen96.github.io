**领导：**昨天你给客服 Agent 写了任务卡，今天它又说看不见订单。客户明明报了 0823，这玩意儿是选择性失明？

**小陈：**它只拿到了一个**号码**，没拿到号码背后的**记录**。您把快递单号念给我，我也不能凭语气听出包裹是不是在门卫室。

**领导：**大模型不是学过那么多东西吗？

**小陈：**学过怎么理解语言，不等于进得了咱们公司的订单库。它能看见什么，取决于这次请求里，业务应用给了什么；要拿实时记录，应用得连接获准使用的查询能力，再把结果交给模型。[OpenAI 的工具调用说明](https://developers.openai.com/api/docs/guides/function-calling)也把访问外部数据放在应用与工具的连接里。订单号只是查询条件，不是查询结果。

**领导：**那上回它回答“昨晚八点签收”，语气还挺肯定。

**小陈：**这正是麻烦。先看这轮输入究竟有什么。下面两次都是**教学模拟**，不是真查了订单 0823。

| 谁说的 | 第一次送给模型的内容 |
| --- | --- |
| 客户 | “订单 0823 显示已签收，可我没收到，能退款吗？” |
| 公司应用 | “请整理一张内部处理卡。” |
| 订单系统 | 没查询，所以没有返回记录 |

**小陈：**在这份输入里，“显示已签收”是**客户转述**；具体签收时间、签收人、退款状态，一项都没有核实。它要是补出“20:08 由前台签收”，那叫编故事，不叫查单。

**领导：**我给模型开网页搜索，它是不是就能找到？

**小陈：**公开网页找不到咱们内部订单。就算您去年把一张订单截图贴给它，那也只是去年的截图；**此刻的订单状态**仍要看本轮被授权的查询结果。“能搜网页”和“能查公司订单”，中间隔着数据、权限和时间，不是多装一个搜索框就通了。

**领导：**总不能每次都回客户“我不知道”吧？

**小陈：**给客服看的内部卡可以写：“客户称页面显示已签收，自述未收到；订单记录尚未核验，需查询。”然后应用去查，只读查询返回什么，再让模型处理什么。**模型负责读结果、组织话；订单系统负责给事实。**

**领导：**好，假设查完了呢？

**小陈：**假设订单系统在演示里返回一条记录：`订单 0823，物流状态：已签收，查询时间：10:15`。这时内部卡可以写：

> 客户反馈：未收到货。来源：本次工单。<br>
> 系统记录：物流状态为“已签收”。来源：订单系统本轮查询，10:15。<br>
> 待核实：签收记录与实际收货情况；退款条件尚未判断。

**领导：**系统都说签收了，还要“待核实”？

**小陈：**系统记录和客户经历是两条不同的线索。系统状态能证明“系统里这样记”，不能证明“客户手里有货”。况且这一轮我只给了订单状态，**没给现行售后规则**，它就不能顺势宣布“不能退”或“必须退”。规则要另外从受控来源提供。

**领导：**你把“来源”写得跟财务报销一样。

**小陈：**差不多。每个关键说法都贴一张小票：客户说的、系统查的、规则写的，别混。明天客户拿着截图来问“你们凭什么说我签收”，客服能回到那次查询记录，而不是说“AI 当时觉得挺像”。

**领导：**给开发一句明确要求。

**小陈：**做一张**输入来源图**，每轮保存模型实际可见的材料与来源：客户原话、订单查询结果、规则片段，缺了哪项就标未知。给客服看的处理卡按来源区分“客户称”和“系统显示”。为减少数据暴露，只传完成这张任务卡所需的信息；查询权限由应用控制。

**领导：**查询接口万一报错呢？是不是写“订单不存在”？

**小陈：**不行。“没调用”“调用失败”“明确返回无此订单”是三种不同情况。调用失败，卡上写“本轮查询失败，状态未知”；只有接口成功返回“无此订单”，才能写“系统未找到该订单”，还得提示客服核对订单号。别让一个网络超时替客户宣判订单消失。

**领导：**怎么知道他们没偷偷靠模型“猜对”了？

**小陈：**回放两遍：第一遍屏蔽订单查询结果，处理卡不得出现签收时间、签收人、退款进度等具体记录；第二遍放入模拟查询结果，卡片只能引用返回的字段，还得写明来源和查询时间。两遍都能过，才说明“知道”有来路。

**小陈：**再加一次查询超时回放。看它能否写“未知并转人工”，而不是把上一次演示的“已签收”抄过来。三份输入分别保存，谁都能复查。

**领导：**行。以后它说“查到了”，先把那张小票给我看。

**小陈：**这句比“相信 AI”省客服工时。
