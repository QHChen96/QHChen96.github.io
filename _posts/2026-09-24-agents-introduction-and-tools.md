周五下午五点五十八分，我把周报发给领导。三分钟后，消息弹了出来。

> 领导：“小陈，这版再短一点。但风险和依据要写全。”<br>
> 我：“好，我改。”<br>
> 我心里：“短一点”和“写全”，这是要我给周报装压缩包吗？

我叫小陈，平时写代码，周五写周报。那天桌面上躺着 `周报_v7_真的最终版.docx`。同事看我还在翻任务卡，问：“你怎么不用 Agent 帮忙查？”

我对“AI 一键搞定”这几个字向来有点警惕。按键可能只要一秒，给错误周报善后要用一周。但这次我确实需要一位能翻资料、找矛盾的帮手。下面这件事，就是我怎么用 Agent 把周报交出去的。**故事和任务编号是虚构示例，做法可以照着用。**

## 领导到底要什么？我先问了一句

我没急着删字，先回了条消息：“您是想先看到结论，细节放在后面，还是整篇都缩短？”领导说：“先给我结论。风险别藏着，问你时能说清从哪来的。”

这下明白了：他要的是**第一屏短，往下能查清**。我把周报改成两层：开头只有结论、进展、风险三行；细节放在后面的依据表。可问题来了——“登录改造已完成”写在任务卡上，会议纪要却说“还在测试”。我不能挑一句好看的抄。

## Agent 上场：先查矛盾，再写稿

我先在工具侧只接了**查询**，没给它修改任务和发送消息的工具，再写下这张任务单。只把这段话贴进普通聊天框，并不会让它凭空看到公司的任务系统；只在提示词里写“不要发送”，也代替不了真正的权限设置。

```text
目标：整理本周登录改造进展，生成给领导看的周报草稿。
资料：只读取我指定的任务卡、会议纪要和测试记录。
要求：先给三行摘要，再列详细依据；每项事实标明来源。
遇到资料冲突：列出冲突，不要猜哪个对，等我确认。
权限：不得修改任务、不得发邮件或群消息。
```

它先读任务卡，看到“接口联调完成”；再读会议纪要，看到“仍在测试”。它没把其中一句扔掉，而是把两条摆在一起问我。我找开发同事确认：**接口联调确实完成了，正在进行的是安全测试**。原来不是两份资料互相打脸，是我们把两个阶段都叫成了“测试”。我把确认结果补回任务记录，Agent 才继续整理草稿。

这就是 Agent 真正帮上忙的地方：它按目标决定下一步，调工具查资料，看完结果发现疑点，再回头找证据或来问我。它的工作不是“写得像真的”，而是**把不确定的地方揪出来**。[OpenAI Agents SDK](https://openai.github.io/openai-agents-python/)把工具、交接和校验列为核心机制；[Anthropic 的工程文章](https://www.anthropic.com/engineering/building-effective-agents)也用“模型动态决定步骤和工具”解释 Agent。

我顺手把几个容易混的词记下来，免得下次开会把“知识库”和“记忆”说成一回事：

| 名词 | 说人话 | 这次怎么用 |
| --- | --- | --- |
| **模型** | 负责理解和判断的“大脑” | 看出两份记录可能说的是不同阶段 |
| **工具** | 让它能查或做事的“手” | 读取任务卡、会议纪要 |
| **知识库** | 可搜索的“资料柜” | 这次没用到；项目规范等资料可以放这里 |
| **状态或记忆** | 手边的“便签” | 记住哪些记录已查、哪里待确认 |

资料柜里有文件，不代表每次都能搜对；便签记得住进度，也不能保证原始资料正确。[Coze 对知识与记忆的说明](https://www.coze.com/open/docs/guides/knowledge_overview)和 [LangGraph 对状态的说明](https://docs.langchain.com/oss/python/langgraph/overview)把这层区别讲得更细。

## 同事问：“这和直接让 AI 写有什么区别？”

我给他看了同一件事的三种做法。区别不在名字听起来多厉害，而在**下一步由谁决定**。

<figure>
  <img src="{{ '/assets/images/workflow-vs-agent.svg' | relative_url }}" alt="普通模型调用一次回答；工作流按预设步骤运行；Agent 根据中间结果动态选择动作" width="960" height="400">
  <figcaption>图 2：资料齐、步骤固定时，真没必要为了叫 Agent 而叫 Agent。</figcaption>
</figure>

- **普通聊天**：我把资料全贴进去，模型改写一版。适合润色；漏贴的会议纪要，它不会自己发现。
- **工作流 Workflow**：我预先定好“取数据 → 排版 → 发我审核”。每周来源固定，这样做很稳。
- **Agent**：看到任务卡和纪要不一致，它临时去查测试记录；还不清楚就停下来问我。下一步跟着发现的问题变。

这份周报最后用的是**固定流程收集资料，Agent 处理说不清的地方，我审核后发送**。没有让 Agent 包揽一切。步骤早就知道的部分交给工作流，碰到意外才让 Agent 判断；[Anthropic 的指南](https://www.anthropic.com/engineering/building-effective-agents)也推荐按任务需要选择这两种方式。

## 我交出去的周报长什么样？

这是那份周报的缩写示例。第一屏只有三行，领导能很快看到结论；要追问，下面有记录可查。

> **结论：**登录改造的接口联调已完成，安全测试仍在进行。灰度时间等测试结果确认。<br>
> **本周进展：**接口联调完成；安全测试进行中。<br>
> **当前风险：**安全测试尚未结束，是否影响灰度时间暂时无法判断；测试结论出来后更新排期。

| 要点 | 依据 | 我做的核对 |
| --- | --- | --- |
| 接口联调完成 | 任务卡 LOGIN-42 | 与开发同事确认“完成”指接口联调 |
| 安全测试进行中 | 9 月 23 日会议纪要 | 确认它和“联调完成”是两个阶段 |
| 灰度时间待定 | 当前无已批准的测试结论 | 不填猜出来的日期，等结论后更新 |

> 领导：“所以现在不是‘完成了还能测试’？”<br>
> 我：“对，联调完成，安全测试没结束。我把两个阶段拆开写了，依据在下面。”<br>
> 领导：“这样就清楚了。”

原来“要短，还要全”没有要求我把十页塞进三行。**先给判断，再把证据放在读者伸手能找到的地方**，问题就解决了一半。另一半，是别把不知道的事写成已经确定。

## 市面上七款产品，我该选谁？

这时领导又问：“你用的那个 Agent，公司以后能不能也做一个？”我一搜，发现产品名字像在招聘会排队，岗位却完全不同：有的直接帮程序员干活，有的用来搭 AI 应用，有的是开发框架。

<figure>
  <img src="{{ '/assets/images/agent-product-map.svg' | relative_url }}" alt="Agent 产品分为直接使用、可视化搭建和代码框架三类" width="960" height="414">
  <figcaption>图 3：先问要解决什么麻烦，再问选哪款产品。</figcaption>
</figure>

| 产品 | 它适合的活 | 放到这件事里怎么看 |
| --- | --- | --- |
| [Codex](https://openai.com/index/introducing-the-codex-app/) | 理解代码仓库、改文件、验证结果 | 开发组要写周报系统的代码，可以用它；它本身不是现成的公司周报系统 |
| [Claude Code](https://code.claude.com/docs/en/overview) | 在终端、IDE 等环境处理开发任务 | 同样适合帮开发组改系统，改动要审阅 |
| [Coze](https://www.coze.com/open/docs/guides/features) | 用提示词、插件、知识库和工作流搭助手 | 要做一个能回答项目文档问题的助手，可从这里试 |
| [Dify](https://docs.dify.ai/en/learn/key-concepts) | 用可视化方式搭聊天应用或工作流 | 要让同事填资料、生成草稿，可看它的 Chatflow 或 Workflow |
| [n8n](https://docs.n8n.io/integrations/builtin/cluster-nodes/root-nodes/n8n-nodes-langchain.agent/) | 串接业务系统和自动化步骤 | 每周固定从任务系统取数、交给人审核，它很对路 |
| [OpenAI Agents SDK](https://openai.github.io/openai-agents-python/) | 用代码定义 Agent、工具和校验 | 公司要把“查矛盾再成稿”写进自家产品时可用 |
| [LangGraph](https://docs.langchain.com/oss/python/langgraph/overview) | 精细控制有状态、可暂停的流程 | 任务跨很多环节、需要中断后继续时再考虑 |

这是我按各家**官方文档**做的用途判断，不是统一跑分，也没有假装七款都装起来测过。产品功能、套餐和模型调用成本会变，采购前还得看最新说明。

我给领导的建议很具体：**眼下只有我每周写一份，就先从任务系统导出记录，连同会议纪要交给公司允许使用的 AI 工具，按“三行摘要＋依据表”出草稿，由我核对后发出。**全组都要做、数据分散在多个系统时，再用 n8n 一类工具把固定取数连起来；需要跟文档来回问答，可以试 Coze 或 Dify；真要做进公司产品，再让开发组评估 SDK 或 LangGraph。Codex 和 Claude Code 可以帮开发组造这个系统，但它们本身不是给全公司直接交周报的成品。

最后，领导看着我那三行摘要说：“这版可以。下周也按这个来。”我默默把文件名改成 `周报_有依据版.docx`。这名字不够霸气，但比“真的最终版”靠谱多了。
